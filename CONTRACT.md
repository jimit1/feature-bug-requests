# CONTRACT.md: the exact shapes every file uses

Three people build this in parallel: the pipeline (`run.py`, prompts, tests), the page (`ui/index.html`), and the ask command (`ask.py`). They meet only at the files below. Follow these shapes exactly. If you need a field that is not here, add it here first in your branch and say so in your final report.

## Mock data (already in `data/`, do not modify)

- `data/gong/<call_id>.json`: `{"call": {"metaData": {id, title, started, duration, ...}, "parties": [{speakerId, name, title, emailAddress, affiliation: "External"|"Internal"}]}, "transcript": {"callId", "transcript": [{"speakerId", "sentences": [{"start": ms, "end": ms, "text"}]}]}}`. One transcript entry is one turn. A turn's locator is `call_id`, `speaker_id`, `start_ms` = first sentence start, `end_ms` = last sentence end. Map `speakerId` to `parties[].speakerId` for the name; `affiliation == "External"` means the customer side. Account: match the External party's email domain to `data/accounts.json` `domain`.
- `data/salesforce/<case_id>.json`: `{"case": {Id, CaseNumber, AccountId, Subject, Status, Priority, CreatedDate, ClosedDate}, "comments": [{Id, ParentId, CommentBody, IsPublished, CreatedById, CreatedDate}]}`. A comment with `IsPublished: false` is an internal note and is never shown to a reader. Author name comes from `data/users.json` (`records[].Id` to `Name`). Account: `case.AccountId` matches `accounts[].record.Id`.
- `data/accounts.json`: `{"accounts": [{account_id, account_type: "customer"|"prospect", domain, record: {Id, Name, Tier__c, ARR__c, Renewal_Date__c}}]}`.
- Which day a document belongs to: Gong `metaData.started[:10]`, Salesforce the comment's `CreatedDate[:10]` (a case can contribute comments on several days; a reader sees the whole thread but may only cite comments from the day being run).

## `library/claims/<YYYY-MM-DD>.jsonl`, one object per line

```json
{"id": "c-3f9a1c2b7d4e", "day": "2026-09-08", "source": "gong", "type": "bug",
 "topic": "renewal statements drop the carried-over balance",
 "quote": "Every renewal statement we send out is missing the balance that carried over from the previous period, so the invoice total reads far higher than it should.",
 "account_id": "ACC-0001", "account": "Great Lakes Museum Alliance", "account_type": "customer",
 "tier": "Enterprise", "arr": 340000, "speaker": "Rhonda Calloway",
 "locator": {"call_id": "7782934451002", "speaker_id": "4521", "start_ms": 663288, "end_ms": 722760},
 "occurred_at": "2026-09-08T15:12:15Z"}
```

Salesforce locator: `{"case_id": "5008W00002aQpLrQAK", "comment_id": "00a8W00000XfT2mQAF"}`. `id` is `"c-"` plus the first 12 hex of sha256 over `source + locator json + quote`, so the same claim never gets two ids. `type` is only `bug` or `feature`. Everything except `type`, `topic`, `quote`, `speaker`, `locator` is filled in by code, not the model.

`library/claims/rejected.jsonl`: the same object plus `"reason": "quote not found in cited turn"` (or `"malformed"`, `"internal comment"`, `"unknown speaker"`).

```json

 "accounts": {"customer": 2, "prospect": 0}, "open_cases": 3,
 "score": 80, "score_parts": {"accounts": 15.0, "value": 24.7, "cases": 20.0, "recency": 10.7, "bug": 10.0},
 "first_seen": "2026-09-08", "last_seen": "2026-09-10",
 "log": [{"day": "2026-09-08", "action": "open", "claim_id": "c-3f9a1c2b7d4e", "why": "one sentence from the editor"},
         {"day": "2026-09-10", "action": "append", "claim_id": "c-9b0e44d1a7c2", "why": "..."}]}
```

`library/themes/index.md`: one line per theme, `THEME-0001 | bug | Renewal invoices ignore credits and mid-year upgrades | 2 accounts | last 2026-09-10`. This file is what the editor reads first. Regenerate it fully after every run.

`library/state.json`: `{"days": ["2026-09-08", "2026-09-09"], "next_theme": 3}`.

## Scoring (code, weights in `config.json`)

`accounts = 30 * min(distinct_accounts, 4) / 4`, `value = 25 * min(max_arr, 500000) / 500000`, `cases = 20 * min(open_cases_on_those_accounts, 4) / 4`, `recency = 15 * max(0, 14 - days_since_last_seen) / 14` where today is the day being run, `bug = 10 if type == "bug" else 0`. `score = round(sum)`. Store the parts so the page can show the arithmetic.

## `ui/data.js` (regenerated by `run.py` after every run; the page's only input)

```js
window.DIGEST = {
  "generated": "2026-09-25",
  "days": ["2026-09-08", "...", "2026-09-25"],
  "themes": [ /* every library/themes/*.json object, sorted by score desc, each with an added "claims": [ /* the full claim objects for its claim_ids */ ] */ ]
};
```

Nothing else. The page must render from this alone, opened from disk, no network.

## Model calls

`run.py` and `ask.py` each read `ANTHROPIC_API_KEY` from the environment and use the `anthropic` package `messages.create`. System prompt is the file under `agents/`. The model must return JSON only; parse with `json.loads` after stripping any code fence; on failure log and drop, never retry more than once, never patch.

## Reader output (what the model returns, before code enriches it)

```json
{"claims": [{"type": "bug", "topic": "...", "quote": "...", "speaker": "Rhonda Calloway",
             "locator": {"call_id": "...", "speaker_id": "...", "start_ms": 0, "end_ms": 0}}]}
```

## Editor output

```json
{"decisions": [{"claim_id": "c-...", "action": "append", "theme_id": "THEME-0002", "title": null, "why": "..."},
               {"claim_id": "c-...", "action": "open", "theme_id": null, "title": "New theme title", "why": "..."}],
 "summaries": {"THEME-0002": "Two plain sentences.", "NEW-1": "..."}}
```

For `open`, code assigns the next `THEME-xxxx` id; the editor refers to a newly opened theme in `summaries` by its `title`. Two claims in the same run may open the same new theme: the editor uses the same `title` for both and code opens it once.
